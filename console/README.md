# Standalone analyst console

`console/index.html` is a self-contained workbench: open the file, paste a threat report
or a log excerpt, and it extracts, scores and explains the indicators — no server, no
build step, no network.

It is **not** a replacement for the dashboard in `app/static/`. That one is the API
client: it authenticates, calls `/api/indicators`, and shows what the backend has stored.
This one runs entirely in the browser against material you paste in, which makes it
useful in places the API is not — a locked-down analyst laptop, an air-gapped review, a
quick triage before you decide anything is worth storing.

```
app/static/index.html   →  the product UI, talks to the FastAPI backend
console/index.html      →  a standalone tool, talks to nothing
```

## Running it

Open `console/index.html` in a browser. That is the whole procedure.

## What it computes

The same class of analysis as `app/ioc/` — deliberately, so the two agree — implemented
in JavaScript so it can run without the backend:

| Step | Detail |
|---|---|
| Refang | Bracketed forms only (`evil[.]com`, `hxxp://`, `user[at]host`), so prose is never mangled |
| Extract | IPv4, domains, URLs, MD5/SHA-1/SHA-256, e-mails, CVEs, with URL spans claimed first |
| Filter | TLD must exist; RFC1918, loopback, link-local, CGNAT, documentation and multicast dropped — each rejection shown with its reason |
| Enrich | Shannon entropy, natural-bigram share, TLD abuse weighting, credential-phishing keywords, homograph and punycode detection, URL shape |
| Score | Weighted sum, 0–100, with every contributing factor and its delta returned |
| Detect | Expression rules over the indicator context, parsed by recursive descent |
| Behavioural | Brute force in a true sliding four-minute window; transfer outliers at z ≥ 3, refusing to report below eight baseline samples |
| Export | STIX 2.1 bundle with deterministic ids, and CSV |

Every score is displayed as a ledger — `source baseline +38`, `TLD weighting +18`,
`DGA likelihood +31` — and the DGA figure itself decomposes into its five measured
components. An end-to-end test asserts that the deltas sum to the number on the gauge.

## The engine

`engine/engine.js` is one file with no dependencies, exported for both the browser and
Node. `console/index.html` is generated by inlining it into `console/app.template.html`:

```bash
node tests/js/build.js
```

CI fails if the committed `console/index.html` does not match what the sources produce,
so the two cannot drift.

## Tests

```bash
node tests/js/engine.test.js     # 89 unit tests
npm install --no-save playwright && npx playwright install chromium
node tests/js/e2e.test.js        # 28 browser tests
```

The unit tests assert values that can be checked by hand — entropy of `abcd` is exactly
2 bits, the sample standard deviation of `2 4 4 4 5 5 7 9` is 2.13809, every RFC-defined
address range — rather than merely that the code ran. One test greps the engine source
for `eval(` and `new Function(` and fails if either appears.

## Where the two implementations could diverge

`app/ioc/parser.py`, `scoring.py` and `enrich.py` do the same job server-side. They are
independent implementations, which means they can drift. If you change scoring in one,
change it in the other — or, better, treat the Python side as authoritative and have the
console call the API when one is reachable, keeping the local engine as the offline path.

That reconciliation is not done yet, and this note exists so nobody assumes it is.
